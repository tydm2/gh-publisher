# 多语言发布协议（i18n）

`gh-publisher` v1.3.0+ 在发布时附带 GitHub 最常用 10 种自然语言的版本，本地工作副本保留你选定的语言。**多语言步骤是技能/文档项目的推送默认步骤**——本文件是该流程的唯一事实源。

## 0. 自动触发与执行流程（v1.6.0）

- **触发**：推送技能或文档项目（源目录含 `SKILL.md`、`README.md` 或其他面向用户的文档）时**默认执行** 6 语言步骤。
- **豁免**：用户明确说「单语言推送/不用翻译/不翻译」→ 跳过生成；如已有语言文件仍跑 `-Languages` 检查。
- **执行流程（agent）**：
  1. 识别主版 README（源语言，通常 en 或项目工作语言）及其内容版本。
  2. 列 6 种发布语言（en、zh-CN、es、fr、ja、ru）；对每个**已有旧译文**的语言，按「省 token 固定方案（增量编辑翻译）」更新（见 §1.5）；**无旧译文**的语言做一次全文翻译（同时建立术语基线）。
  3. 跑 `push.ps1 -Languages en,zh-CN,es,fr,ja,ru`（缺失列 WARN）；加 `-RequireI18n` 硬性把关——缺失语言文件即 FAIL 中止（exit 1）。
  4. 推送。
- **范围**：README 全量翻译（6 语言）。`SKILL.md` 保持**单一主版语言**（技能系统每目录只加载一份 SKILL.md）；`references/` 与 `scripts/` 为技术内容，不翻译。

## 1.5 省 token 固定方案：增量编辑翻译（v1.5.0，★默认，不再全文重翻）

**为什么**：全文重翻时 token 大头花在重写未变化的段落上，且易引入术语/风格漂移。增量编辑只重译变化段落，省 ~70-90% 输出 token、更快、且天然保持旧译文的术语与文风。

**步骤（每个语言一个并行子代理）**：
1. 子代理先**读**英文源 `README.md`（新版本）与目标语言的旧译文 `README.<lang>.md`。
2. 用**文件编辑操作**（增量修改，如编辑工具替换段落，而非重写整个文件）逐段处理旧译文：
   - 英文源**未变**的段落 → 旧译文**原样保留**（不重新生成）；
   - 英文源**变化**的段落 → **只重译该段**；
   - 英文源**新增**的段落 → 新译并插入对应位置；
   - 英文源**删除**的段落 → 从旧译文移除。
3. **保留清单（readme-i18n 同款）**：语言切换栏（就地更新，不重复添加）、徽章（**URL 必须原样**；alt/可见文本仅在 URL 不变时可译）、全部链接与锚点（含徽章引用的 `#disclaimer` 等）、代码块、**项目名/包名/命令/CLI flags/选项名/环境变量/文件名**——一律不译。
4. **术语一致**：沿用旧译文已有术语；英文源新增术语按领域惯例翻译，各语言保持一致（同义反复时以先翻译语言的用词为准）。
5. 完成后主 agent 抽查：语言栏未重复、锚点未断、版本徽章正确、无整段重翻痕迹。

**首次翻译（无旧译文）**：全文翻译一次；同时把关键术语（skill 名、机制名、专有名词）的译法记为术语基线，后续版本沿用。

## 1.6 效率要点（v1.6.0）

| 手段 | 效果 | 说明 |
|------|------|------|
| 发布语言 10→6（en/zh-CN/es/fr/ja/ru） | 翻译量 −40% | 砍掉 hi/ar/bn/pt；如需可再加回 |
| 增量编辑翻译（§1.5） | 输出 token −70~90% | 有旧译文默认增量，不全文重翻 |
| 代码块/保留清单**字节级不动** | 免重译 token | 代码块、文件名、URL、触发词一律原样复制，子代理校验一致 |
| 语言栏只列 6 种发布语言 | 无死链 + 内容更短 | 不引用未发布语言（README.hi.md 等已不在发布集） |
| 并行子代理 | 墙钟时间 −~70% | 每语言一个子代理同时翻译，主 agent 只抽查 |

> 语言栏模板（v1.6，6 语言，各自语言加粗）：
> `[English](README.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · [Français](README.fr.md) · [Русский](README.ru.md) · [日本語](README.ja.md)`

## 1. 本地语言（工作副本）

- 配置：已安装技能目录的 `config.local.json`：`{"local_lang": "zh"}`（默认）或 `{"local_lang": "en"}`。
- 本地 `SKILL.md` 用配置的语言书写；agent 在产出或编辑本地文档前必须先读该配置。
- 切换：用户说「更改本地保留默认语言为英文」→ 更新 `config.local.json` 并把本地 SKILL.md 重写为对应语言（frontmatter 契约冻结：`name` 不变、`description` 保持触发语义）。

## 2. 发布语言 —— 6 种发布语言（v1.6.0）

按 GitHub 用户人口与项目受众价值选取（中英 + 西法日俄），相比原 10 语言砍掉 hi/ar/bn/pt（翻译量 −40%）：

| 代码 | 语言 | README 文件 |
|------|------|-------------|
| en | 英语 | `README.md` |
| zh-CN | 简体中文 | `README.zh-CN.md` |
| es | 西班牙语 | `README.es.md` |
| fr | 法语 | `README.fr.md` |
| ru | 俄语 | `README.ru.md` |
| ja | 日语 | `README.ja.md` |

> 旧版 `README.de.md` / `README.ko.md`（v1.0.0 快照）与 v1.5 前的 `README.hi/ar/bn/pt.md` 保留兼容（已发布版本不回删），但**不再新增**，也不属于 6 语言集。

## 3. 文件布局

```
release-dir/
  SKILL.md                  # 英文通用主版（技能系统每个目录只加载一份 SKILL.md）
  README.md                 # en
  README.zh-CN.md           # zh-CN
  README.<lang>.md          # 每个发布语言一份
  references/i18n.md        # 本文件（en）
  references/security.md    # en
  references/platform-adapter.md
  scripts/push.ps1
  CHANGELOG.md
  LICENSE
```

- 发布版 `SKILL.md` 保持**英文**：技能系统每个目录只加载一份 SKILL.md，多语言 SKILL 会冲突；语言由 README 承载。

## 4. 翻译规范

1. 翻译完整 markdown，保留：语言切换栏、徽章（License/Version/AI-crafted）、全部链接（不要本地化 URL）、代码块、被引用的标题锚点。
2. 每种语言版本 `name: gh-publisher` 保持一致（触发契约冻结）；`description` 若翻译须保持相同触发语义。
3. 不杜撰内容；术语与 `references/i18n.md` 和 `README.md`（英文源）保持一致。
4. RTL 语言（ar）在 Markdown 中无需版式调整；切换栏顺序保持不变。
5. **不译清单（readme-i18n 同款，v1.5）**：项目名、包名、命令、CLI flags、选项名、环境变量、文件名、URL、徽章 URL；徽章 alt 文本仅在 URL 不变时可译。
6. 翻译后验证每个文件可渲染（相对链接不坏），再以 `-Languages en,zh-CN,es,fr,ja,ru` 推送。

## 5. 就绪检查

`push.ps1 -Languages <清单>` 在批量提交前校验 `-Source` 下每种 `README.<lang>.md` 存在；缺失列 WARN（推送继续）。先翻译、再推送。

## 6. 安全说明

- 翻译由 agent（LLM）生成；上线前审查上游内容是否混入提示注入产物。
- 任何语言版本不得出现密钥、个人数据或私有上下文。
