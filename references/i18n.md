# Multilingual publish protocol (i18n)

`gh-publisher` v1.3.0+ publishes files in GitHub's 10 most-used natural languages while the local working copy stays in your preferred language. **The multilingual step is a DEFAULT push step for skill/doc projects** — this file is the single source of truth for that flow.

## 0. Auto-trigger & execution flow (v1.3.0)

- **Trigger**: pushing a skill or documentation project (source contains a `SKILL.md`, `README.md`, or other user-facing docs) **defaults to** the 10-language step.
- **Opt-out**: the user explicitly says "single-language push / no translations / don't translate" → skip the generation; still run the `-Languages` check if files exist.
- **Execution flow (agent)**:
  1. Identify the primary README (the source language, usually en or the project's working language) and its content version.
  2. List the 10 release languages (en, zh-CN, hi, es, fr, ar, bn, pt, ru, ja). For each language that **already has an old translation**, update it via the **token-efficient fixed scheme** (§1.5 incremental-edit translation); for each language with **no old translation**, do a full first translation (this also establishes the terminology baseline).
  3. Run `push.ps1 -Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja` (WARN on missing). Add `-RequireI18n` for hard enforcement: missing files then FAIL the push (exit 1).
  4. Push.
- **Scope**: READMEs are translated in full (10 languages). `SKILL.md` stays in ONE primary language (skill systems load a single SKILL.md per directory); `references/` and `scripts/` are technical content and are not translated.

## 1.5 Token-efficient fixed scheme: incremental-edit translation (v1.5.0, ★default — no more full re-translation)

**Why**: full re-translation spends most tokens rewriting paragraphs that did not change, and drifts terminology/style. Incremental edits re-translate only the changed paragraphs — roughly **70-90% less output token**, faster, and the unchanged parts of the old translation stay byte-identical.

**Steps (one parallel subagent per language)**:
1. The subagent first **reads** the English source `README.md` (new version) and the target language's old translation `README.<lang>.md`.
2. Apply **file-edit operations** (incremental edits — e.g. replace the changed paragraphs, never rewrite the whole file) paragraph by paragraph:
   - English source **unchanged** paragraphs → keep the old translation **as-is** (do not regenerate);
   - English source **changed** paragraphs → re-translate **only that paragraph**;
   - English source **new** paragraphs → translate and insert at the matching position;
   - English source **removed** paragraphs → remove them from the old translation.
3. **Preserve list (readme-i18n style)**: the language-switcher bar (update in place, never duplicate it), badges (**URLs verbatim**; alt/visible text may be translated only when the URL does not change), all links and anchors (including badge-referenced `#disclaimer` etc.), code blocks, **project names / package names / commands / CLI flags / option names / environment variables / file names** — never translated.
4. **Terminology consistency**: reuse the old translation's established terms; for new English terms, translate per domain convention and keep them consistent across all languages (when in doubt, follow the language that was translated first).
5. After all languages are done, the main agent spot-checks: no duplicated language bar, no broken anchors, correct version badge, no wholesale re-translation artifacts.

**First translation (no old translation)**: translate the full file once; record the chosen renderings of key terms (skill name, mechanism names, proper nouns) as the **terminology baseline** for future versions.

## 1. Local language (working copy)

- Config: `config.local.json` in the installed skill dir: `{"local_lang": "zh"}` (default) or `{"local_lang": "en"}`.
- The local `SKILL.md` is written in the configured language; agents must read the config before producing or editing any local doc.
- Switch: user says e.g. *"change local default language to English"* → update `config.local.json` and rewrite the local SKILL.md to match (frontmatter contract frozen: same `name`, trigger-preserving `description`).

## 2. Release languages — GitHub's 10 most-used natural languages

Order by GitHub user population (industry consensus data):

| Code | Language | README file |
|------|----------|-------------|
| en | English | `README.md` |
| zh-CN | Simplified Chinese | `README.zh-CN.md` |
| hi | Hindi | `README.hi.md` |
| es | Spanish | `README.es.md` |
| fr | French | `README.fr.md` |
| ar | Arabic | `README.ar.md` |
| bn | Bengali | `README.bn.md` |
| pt | Portuguese | `README.pt.md` |
| ru | Russian | `README.ru.md` |
| ja | Japanese | `README.ja.md` |

> Older `README.de.md` / `README.ko.md` (v1.0.0 snapshots) are kept for compatibility but are not part of the 10-language set.

## 3. File layout

```
release-dir/
  SKILL.md                  # English universal primary (single SKILL.md per skill system)
  README.md                 # en
  README.zh-CN.md           # zh-CN
  README.<lang>.md          # one per release language
  references/i18n.md        # this file (en)
  references/security.md    # en
  references/platform-adapter.md
  scripts/push.ps1
  CHANGELOG.md
  LICENSE
```

- `SKILL.md` stays **English** in the release: skill systems load exactly one `SKILL.md` per directory, so multilingual SKILL files would conflict. READMEs carry the languages.

## 4. Translation rules

1. Translate the full markdown, preserving: the language-switcher bar, badges (License/Version/AI-crafted), all links (do not localize URLs), code blocks, headings anchors where referenced.
2. Keep `name: gh-publisher` identical in every language version (trigger-contract freeze). `description` must keep the same trigger semantics if translated.
3. Do not invent content; keep terminology consistent with `references/i18n.md` and `README.md` (en source of truth).
4. RTL scripts (ar) need no layout changes in Markdown; keep the switcher bar order as-is.
5. **Do-not-translate list (readme-i18n style, v1.5)**: project names, package names, commands, CLI flags, option names, environment variables, file names, URLs, badge URLs; badge alt text may be translated only when the URL does not change.
6. After translation: verify each file renders (no broken relative links), then push with `-Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja`.

## 5. Readiness check

`push.ps1 -Languages <list>` verifies every `README.<lang>.md` exists in `-Source` before the batch commit; missing files are listed as WARN (push continues). Translate first, then push.

## 6. Security notes

- Translations are generated by agents (LLM); review for prompt-injection artifacts from upstream content before shipping.
- No secrets, personal data, or private context may appear in any language version.
