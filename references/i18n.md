# Multilingual publish protocol (i18n)

`gh-publisher` v1.2.0+ publishes files in GitHub's 10 most-used natural languages while the local working copy stays in your preferred language. This file is the single source of truth for that flow.

## 1. Local language (working copy)

- Config: `config.local.json` in the installed skill dir: `{"local_lang": "zh"}` (default) or `{"local_lang": "en"}`.
- The local `SKILL.md` is written in the configured language; agents must read the config before producing or editing any local doc.
- Switch: user says e.g. *"change local default language to English"* → update `config.local.json` and rewrite the local SKILL.md to match (frontmatter contract frozen: same `name`, trigger-preserving `description`).

## 2. Release languages — GitHub's 10 most-used natural languages

Order by GitHub user population (industry consensus data):

| Code | Language | README file |
|------|----------|-------------|
| en | English | `README.md` |
| zh-CN | Simplified Chinese | `README.zh-CN.md` |
| hi | Hindi | `README.hi.md` |
| es | Spanish | `README.es.md` |
| fr | French | `README.fr.md` |
| ar | Arabic | `README.ar.md` |
| bn | Bengali | `README.bn.md` |
| pt | Portuguese | `README.pt.md` |
| ru | Russian | `README.ru.md` |
| ja | Japanese | `README.ja.md` |

> Older `README.de.md` / `README.ko.md` (v1.0.0 snapshots) are kept for compatibility but are not part of the 10-language set.

## 3. File layout

```
release-dir/
  SKILL.md                  # English universal primary (single SKILL.md per skill system)
  README.md                 # en
  README.zh-CN.md           # zh-CN
  README.<lang>.md          # one per release language
  references/i18n.md        # this file (en)
  references/security.md    # en
  references/platform-adapter.md
  scripts/push.ps1
  CHANGELOG.md
  LICENSE
```

- `SKILL.md` stays **English** in the release: skill systems load exactly one `SKILL.md` per directory, so multilingual SKILL files would conflict. READMEs carry the languages.

## 4. Translation rules

1. Translate the full markdown, preserving: the language-switcher bar, badges (License/Version/AI-crafted), all links (do not localize URLs), code blocks, headings anchors where referenced.
2. Keep `name: gh-publisher` identical in every language version (trigger-contract freeze). `description` must keep the same trigger semantics if translated.
3. Do not invent content; keep terminology consistent with `references/i18n.md` and `README.md` (en source of truth).
4. RTL scripts (ar) need no layout changes in Markdown; keep the switcher bar order as-is.
5. After translation: verify each file renders (no broken relative links), then push with `-Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja`.

## 5. Readiness check

`push.ps1 -Languages <list>` verifies every `README.<lang>.md` exists in `-Source` before the batch commit; missing files are listed as WARN (push continues). Translate first, then push.

## 6. Security notes

- Translations are generated by agents (LLM); review for prompt-injection artifacts from upstream content before shipping.
- No secrets, personal data, or private context may appear in any language version.
