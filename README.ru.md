**Публикация файлов на GitHub без git — экономично по токенам, безопасно для конфиденциальности, мультиагентно, мультиязычно.**

`gh-publisher` — это навык агента, который публикует локальную директорию в репозиторий GitHub с помощью `gh` CLI + GitHub REST API (Contents / Git Database) — git не требуется. Он обрабатывает инициализацию пустого репозитория и пакетные коммиты одним переиспользуемым скриптом, поэтому агенты публикуют одной командой вместо того, чтобы заново выстраивать весь процесс работы с API. Он также публикует **10 самых используемых языков GitHub** (переводы README), при этом локальная рабочая копия остаётся на предпочитаемом вами языке.

## Почему он выделяется

- **🚀 Публикация без git** — работает на машинах без git; автоматически инициализирует пустые репозитории.
- **⚡ Экономично по токенам** — одна команда `scripts/push.ps1` выполняет сканирование → инициализацию → пакетный коммит → замаскированный вывод (одна строка `PUSHED N files -> URL`) вместо десятков ручных вызовов API.
- **🔒 Конфиденциальность и безопасность аккаунта** — токены хранятся только в keyring `gh` (никогда в чате/логах/файлах); файлы сканируются на наличие секретов перед публикацией (`github_pat_`, `ghp_`, `sk-`, закрытые ключи…); вывод маскируется.
- **🔌 Мультиагентная адаптация** — скрипт `pwsh` работает на Windows/macOS/Linux; задокументированы соответствия DSH / Codex / Claude Code; нет жёстко зашитых имён платформенных инструментов.
- **🧩 Автоматическая инициализация пустого репозитория** — определяет пустые репозитории и загружает первый файл через Contents API перед пакетным коммитом.
- **🌍 Мультиязычная публикация** — локальная рабочая копия остаётся на выбранном вами языке (по умолчанию китайский); релизы включают переводы README для 10 самых используемых языков GitHub (en, zh-CN, hi, es, fr, ar, bn, pt, ru, ja). См. `references/i18n.md`.

## Как это работает

1. `pwsh -ExecutionPolicy Bypass -File scripts/push.ps1 -Source <dir> -Repo owner/repo -Message "msg" [-GhPath <path-to-gh.exe>] [-Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja]`
2. Автоматически находит бинарный файл `gh` (`-GhPath` → PATH → типовые пути установки) и автоматически определяет `GH_CONFIG_DIR` — без ручной настройки PATH/конфигурации.
3. Сканирование на секреты → прерывание при любом совпадении с шаблоном ключа/токена (если не указан `-ForceSecret`).
4. Определение пустого репозитория проверкой ссылки ветки (404 = пустой) → при необходимости загрузка первого файла (Contents API).
5. Пакетный коммит всех файлов (Git Database API: blobs → tree → commit → ref).
6. Выводит `PUSHED N files -> https://github.com/owner/repo` — и ничего больше. Отсутствующий репозиторий → выводит подсказку `gh repo create`.
7. Необязательная проверка `-Languages`: перед публикацией проверяет, что существует файл каждого языка (например, `README.hi.md`), и предупреждает, если какой-то отсутствует.

## Мультиязычная публикация (локальный язык + 10 языков релиза)

- **Локальная рабочая копия**: остаётся на настроенном языке (zh или en) — `config.local.json` в директории установленного навыка (по умолчанию `zh`). Скажите *"change local default language to English"*, чтобы переключить; локальный SKILL.md обновляется соответствующим образом.
- **Релиз**: `SKILL.md` остаётся на английском (универсальный основной язык GitHub), тогда как `README.<lang>.md` публикуется для 10 самых используемых языков. См. `references/i18n.md` — там список языков, правила перевода и примечания о триггер-контракте (все языковые версии сохраняют одинаковый `name`).

## Самопроверка окружения (один раз перед первой публикацией)

- `Get-Command gh` (или позвольте скрипту автоматически определить пути установки); если отсутствует: `winget install GitHub.cli`.
- `gh auth status` показывает вошедший в систему аккаунт (токен замаскирован как `github_pat_***…`).
- `gh api repos/{owner}/{repo}` или `gh repo list` возвращает данные.

## Установка

```
~/.dsh/skills/gh-publisher/    # global
.dsh/skills/gh-publisher/      # per project
```

Запускайте его фразами вроде *"push this to GitHub"*, *"publish this skill to a repo"* — или через пункт меню `/skill` ⑤ в **set-skill**.
