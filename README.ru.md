**Публикация файлов на GitHub без git — экономия токенов, приватность, поддержка нескольких агентов и языков.**

`gh-publisher` — это навык агента, который публикует локальную директорию в репозиторий GitHub с помощью CLI `gh` + REST API GitHub (Contents / Git Database) — git не требуется. Он обрабатывает инициализацию пустого репозитория и пакетную фиксацию изменений одним переиспользуемым скриптом, поэтому агенты выполняют публикацию одной командой вместо повторного вывода всего потока работы с API. Он также публикует **10 самых используемых языков GitHub** (переводы README), пока локальная рабочая копия остаётся на вашем предпочитаемом языке.

## Чем он выделяется

- **🚀 Публикация без git** — работает на машинах без git; автоматически инициализирует пустые репозитории.
- **⚡ Экономия токенов** — одна команда `scripts/push.ps1` выполняет проверку → сканирование → инициализацию → пакетную фиксацию → маскированный вывод (одна строка `PUSHED N files -> URL`) вместо десятков написанных вручную вызовов API.
- **🌍 Экономичные по токенам переводы** — многоязычные README обновляются через **инкрементальное редактирование перевода** (субагенты правят только изменённые абзацы поверх старого перевода, без полного перевода заново): примерно на 70-90% меньше выходных токенов, быстрее, а терминология и стиль остаются стабильными.
- **🔒 Приватность и безопасность аккаунта** — токены хранятся только в связке ключей `gh` (никогда в чате/логах/файлах); перед публикацией файлы сканируются на секреты (`github_pat_`, `ghp_`, `sk-`, приватные ключи…); вывод маскируется.
- **🛡️ Защита личных данных** — машинный локальный профиль (`local-profile.json` / `config.local.json`) **никогда не может** быть опубликован: публикация прерывается в тот момент, когда такой файл появляется в исходной директории, прежде чем выполнится что-либо ещё.
- **🗂️ Машинный локальный профиль** — на машине со сложной сетевой конфигурацией (например, при перехвате хостов) один файл `local-profile.json` объединяет аккаунт, запись gh (прокси-обёртку) и известное сопоставление репозиториев, поэтому для публикации нужен только `-Profile` — больше не нужно искать аккаунт / gh / репозиторий.
- **🔌 Адаптация под несколько агентов** — скрипт `pwsh` работает на Windows/macOS/Linux; сопоставления для DSH / Codex / Claude Code задокументированы; нет жёстко заданных имён платформенных инструментов.
- **🧩 Автоинициализация пустого репозитория** — обнаруживает пустые репозитории и засевает первый файл через Contents API перед пакетной фиксацией.
- **🌍 Многоязычная публикация** — локальная рабочая копия остаётся на выбранном вами языке (по умолчанию китайский); релизы включают переводы README на 10 самых используемых языков GitHub (en, zh-CN, hi, es, fr, ar, bn, pt, ru, ja). См. `references/i18n.md`.

## Как это работает

1. `pwsh -ExecutionPolicy Bypass -File scripts/push.ps1 -Source <dir> -Repo owner/repo -Message "msg" [-Profile <local-profile.json>] [-GhPath <path-to-gh.exe>] [-Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja]`
2. Автоматически находит бинарник `gh` (`-GhPath` → PATH → стандартные пути установки) и автоматически определяет `GH_CONFIG_DIR` — без ручной настройки PATH/конфига. С `-Profile` запись gh, директория конфига, репозиторий (сопоставляется по исходной директории) и языки (автоопределяются по `README.<lang>.md`) разрешаются автоматически.
3. **Защита личных данных** — `local-profile.json` / `config.local.json` в исходной директории → прерывание (они никогда не должны быть опубликованы).
4. Сканирование на секреты → прерывание при любом шаблоне ключа/токена (если не указан `-ForceSecret`).
5. Определение пустого репозитория по проверке ссылки ветки (404 = пусто) → при необходимости засев первого файла (Contents API).
6. Пакетная фиксация всех файлов (Git Database API: blobs → tree → commit → ref).
7. Вывод `PUSHED N files -> https://github.com/owner/repo` — и ничего больше. При отсутствии репозитория выводится подсказка `gh repo create`.
8. Необязательная проверка `-Languages`: подтверждает наличие каждого языкового файла (например, `README.hi.md`) перед публикацией и предупреждает об отсутствующих.

## Многоязычная публикация (локальный язык + 10 языков релиза)

- **Локальная рабочая копия**: остаётся на настроенном вами языке (zh или en) — `config.local.json` в установленной директории навыка (по умолчанию `zh`). Скажите *"change local default language to English"*, чтобы переключить; локальный SKILL.md обновляется соответствующим образом.
- **Релиз**: `SKILL.md` остаётся на английском (универсальный основной язык GitHub), а `README.<lang>.md` публикуется для 10 самых используемых языков. Список языков, правила перевода и заметки о триггерном контракте см. в `references/i18n.md` (все языковые версии сохраняют одно и то же `name`).
- **Экономичная по токенам фиксированная схема**: языки с существующим переводом обновляются через инкрементальное редактирование перевода (правятся только изменённые абзацы — без полного перевода заново); языки, переводимые впервые, получают один полный перевод, который задаёт базовую терминологию. См. `references/i18n.md` §1.5.

## Измеренные результаты: v1.4.0 → v1.5.0 (инкрементальное редактирование перевода)

Обновление README на 11 языках для этого релиза стало первым запуском схемы инкрементального редактирования. Мы сравнили её с прежним полным переводом заново, используя фактические файлы v1.4.0 (полученные из репозитория на коммите `40dcf1f`) против опубликованных файлов v1.5.0 (построчный diff):

| Показатель | Полный перевод заново (эпоха v1.4) | Инкрементальное редактирование (v1.5) | Экономия |
|---|---|---|---|
| Выходной контент, 11 языков | 68,292 символов | 7,717 символов | **88.7%** |
| Примерное число выходных токенов (~3 символа/токен) | ~22,800 | ~2,600 | **~88.7%** |
| Терминология / стиль | могут расходиться от релиза к релизу | старые переводы побайтно идентичны, кроме изменённых абзацев | стабильны |
| Затраты на язык | перегенерировать весь файл | ~4 точечных правки | быстрее |

Доля изменений по языкам (изменённые символы / старый полный файл): zh-CN 9.1% · hi 10.8% · es 11.9% · fr 12.5% · ar 12.2% · bn 11.3% · pt 11.6% · ru 12.0% · ja 8.9% · de 12.3% · ko 9.4% — **фактически изменилось только ~9-12% каждого файла**, поэтому полный перевод заново тратил ~8-11× больше выходных данных, чем требовалось.

*Метод: файлы v1.4.0 получены из репозитория на коммите `40dcf1f`; построчный diff (добавленные/изменённые строки) по каждому языку против опубликованных файлов v1.5.0; токены приближённо оценены как ~3 символа/токен для смешанно-язычных README. Затраты на входной стороне тоже различаются (инкрементальное редактирование читает старый перевод), но выход — доминирующая и самая дорогая часть перевода LLM.*

## Машинный локальный профиль (local-profile)

На машинах с нестандартной сетевой конфигурацией (например, файл hosts, перехватывающий домены GitHub на 127.0.0.1, плюс портативный `gh`, который должен работать через локальную прокси-обёртку), `E:\ds harness\gh\local-profile.json` объединяет владельца, запись gh, директорию конфига и известное сопоставление репозиториев. Файл помечен `"never_publish": true` — он существует только на машине и никогда не публикуется. Любое действие, которое читает/изменяет его, сначала запрашивает явно выделенное подтверждение.

## Самопроверка окружения (один раз перед первой публикацией)

- `Get-Command gh` (или позвольте скрипту автоматически определить пути установки); если отсутствует: `winget install GitHub.cli`.
- `gh auth status` показывает вошедший аккаунт (токен маскирован как `github_pat_***…`).
- `gh api repos/{owner}/{repo}` или `gh repo list` возвращает данные.

## Установка

```
~/.dsh/skills/gh-publisher/    # global
.dsh/skills/gh-publisher/      # per project
```

Запускайте его фразами вроде *"push this to GitHub"*, *"publish this skill to a repo"* — или через пункт меню ⑤ `/skill` в **set-skill**.
