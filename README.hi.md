**बिना git के GitHub पर फ़ाइलें प्रकाशित करें — टोकन-कुशल, गोपनीयता-सुरक्षित, बहु-एजेंट, बहुभाषी।**

`gh-publisher` एक एजेंट स्किल है जो `gh` CLI + GitHub REST API (Contents / Git Database) का उपयोग करके एक स्थानीय निर्देशिका को GitHub रिपॉज़िटरी में प्रकाशित करती है — git की आवश्यकता नहीं। यह एक पुनः-उपयोगी स्क्रिप्ट के साथ खाली-रिपॉज़िटरी आरंभीकरण और बैच कमिट को संभालती है, इसलिए एजेंट पूरी API प्रक्रिया को दोबारा निकालने के बजाय एक ही कमांड में पुश कर सकते हैं। यह GitHub की **10 सबसे अधिक उपयोग की जाने वाली भाषाओं** (README अनुवाद) को भी प्रकाशित करती है, जबकि स्थानीय कार्यशील प्रति आपकी पसंदीदा भाषा में ही रहती है।

## यह क्यों अलग है

- **🚀 बिना git का पुश** — बिना git वाली मशीनों पर काम करता है; खाली रिपॉज़िटरी को स्वचालित रूप से आरंभ करता है।
- **⚡ टोकन-कुशल** — एक ही `scripts/push.ps1` कमांड गार्ड → स्कैन → आरंभ → बैच कमिट → मास्क किया गया आउटपुट (केवल एक `PUSHED N files -> URL` पंक्ति) करता है, दर्जनों हाथ से लिखे API कॉल के बजाय।
- **🌍 टोकन-कुशल अनुवाद** — बहुभाषी README **incremental-edit अनुवाद** के माध्यम से अपडेट होते हैं (सबएजेंट पुराने अनुवाद के ऊपर केवल बदले हुए अनुच्छेद संपादित करते हैं, पूर्ण पुनः-अनुवाद नहीं): ~70-90% कम आउटपुट टोकन, तेज़, और शब्दावली/शैली स्थिर रहती है।
- **🔒 गोपनीयता और खाता सुरक्षा** — टोकन केवल `gh` कीरिंग में रहते हैं (कभी चैट/लॉग/फ़ाइलों में नहीं); पुश से पहले फ़ाइलों की गुप्त-स्कैनिंग होती है (`github_pat_`, `ghp_`, `sk-`, निजी कुंजियाँ…); आउटपुट मास्क किया जाता है।
- **🛡️ व्यक्तिगत-डेटा गार्ड** — मशीन-स्थानीय प्रोफ़ाइल (`local-profile.json` / `config.local.json`) को **कभी** प्रकाशित नहीं किया जा सकता: जैसे ही स्रोत में ऐसी कोई फ़ाइल दिखाई देती है, कुछ और चलने से पहले ही पुश रुक जाता है।
- **🗂️ मशीन-स्थानीय प्रोफ़ाइल** — जटिल नेटवर्किंग वाली मशीन पर (जैसे होस्ट हैजैकिंग), एक `local-profile.json` खाते, gh एंट्री (प्रॉक्सी-मोड शिम) और ज्ञात रिपो मैपिंग को एक जगह समेकित करता है, ताकि पुश के लिए केवल `-Profile` की आवश्यकता हो — अब खाता / gh / रिपो ढूँढने की ज़रूरत नहीं।
- **🔌 बहु-एजेंट अनुकूल** — `pwsh` स्क्रिप्ट Windows/macOS/Linux पर चलती है; DSH / Codex / Claude Code मैपिंग प्रलेखित हैं; कोई हार्डकोडेड प्लेटफ़ॉर्म टूल नाम नहीं।
- **🧩 स्वचालित खाली-रिपो आरंभ** — खाली रिपॉज़िटरी का पता लगाता है और बैच कमिट से पहले Contents API के माध्यम से पहली फ़ाइल का बीजारोपण करता है।
- **🌍 बहुभाषी प्रकाशन** — स्थानीय कार्यशील प्रति आपकी चुनी हुई भाषा में रहती है (डिफ़ॉल्ट चीनी); रिलीज़ में GitHub की 10 सबसे अधिक उपयोग की जाने वाली भाषाओं (en, zh-CN, hi, es, fr, ar, bn, pt, ru, ja) के लिए README अनुवाद शामिल होते हैं। देखें `references/i18n.md`।

## यह कैसे काम करता है

1. `pwsh -ExecutionPolicy Bypass -File scripts/push.ps1 -Source <dir> -Repo owner/repo -Message "msg" [-Profile <local-profile.json>] [-GhPath <path-to-gh.exe>] [-Languages en,zh-CN,hi,es,fr,ar,bn,pt,ru,ja]`
2. स्वचालित रूप से `gh` बाइनरी का पता लगाता है (`-GhPath` → PATH → सामान्य इंस्टॉल पथ) और `GH_CONFIG_DIR` का स्वतः पता लगाता है — कोई मैन्युअल PATH/config छेड़छाड़ नहीं। `-Profile` के साथ, gh एंट्री, कॉन्फ़िग निर्देशिका, रिपो (स्रोत निर्देशिका से मिलान) और भाषाएँ (`README.<lang>.md` से स्वतः पता लगाई गईं) स्वचालित रूप से हल हो जाती हैं।
3. **व्यक्तिगत-डेटा गार्ड** — स्रोत में `local-profile.json` / `config.local.json` → रोक दें (इन्हें कभी प्रकाशित नहीं किया जाना चाहिए)।
4. गुप्त-स्कैन → किसी भी कुंजी/टोकन पैटर्न पर रोक दें (जब तक `-ForceSecret` न दिया गया हो)।
5. ब्रांच ref की जाँच करके खाली रिपो का पता लगाएँ (404 = खाली) → आवश्यकता पड़ने पर पहली फ़ाइल का बीजारोपण (Contents API) करें।
6. सभी फ़ाइलों का बैच कमिट करें (Git Database API: blobs → tree → commit → ref)।
7. `PUSHED N files -> https://github.com/owner/repo` प्रिंट करें — और कुछ नहीं। रिपो नहीं मिलने पर → एक `gh repo create` संकेत प्रिंट करता है।
8. वैकल्पिक `-Languages` जाँच: पुश करने से पहले प्रत्येक भाषा फ़ाइल के मौजूद होने की पुष्टि करता है (जैसे `README.hi.md`) और कोई भी गायब होने पर चेतावनी देता है।

## बहुभाषी प्रकाशन (स्थानीय भाषा + 10 रिलीज़ भाषाएँ)

- **स्थानीय कार्यशील प्रति**: आपकी कॉन्फ़िगर की गई भाषा (zh या en) में रहती है — इंस्टॉल की गई स्किल निर्देशिका में `config.local.json` (डिफ़ॉल्ट `zh`)। स्विच करने के लिए *"स्थानीय डिफ़ॉल्ट भाषा को अंग्रेज़ी में बदलें"* कहें; स्थानीय SKILL.md उसी के अनुसार अपडेट हो जाता है।
- **रिलीज़**: `SKILL.md` अंग्रेज़ी में रहता है (सार्वभौमिक GitHub प्राथमिक), जबकि 10 सबसे अधिक उपयोग की जाने वाली भाषाओं के लिए `README.<lang>.md` प्रकाशित होता है। भाषा सूची, अनुवाद नियम और ट्रिगर-अनुबंध नोट्स के लिए देखें `references/i18n.md` (सभी भाषा संस्करण एक ही `name` रखते हैं)।
- **टोकन-कुशल निश्चित योजना**: जिन भाषाओं का मौजूदा अनुवाद है वे incremental-edit अनुवाद के माध्यम से अपडेट होती हैं (केवल बदले हुए अनुच्छेद संपादित करें — कोई पूर्ण पुनः-अनुवाद नहीं); पहली बार की भाषाओं को एक पूर्ण अनुवाद मिलता है जो शब्दावली आधार-रेखा स्थापित करता है। देखें `references/i18n.md` §1.5।

प्रति-भाषा परिवर्तन अनुपात (परिवर्तित वर्ण / पुरानी पूर्ण फ़ाइल): zh-CN 9.1% · hi 10.8% · es 11.9% · fr 12.5% · ar 12.2% · bn 11.3% · pt 11.6% · ru 12.0% · ja 8.9% · de 12.3% · ko 9.4% — **प्रत्येक फ़ाइल का केवल ~9-12% वास्तव में बदला**, इसलिए पूर्ण पुनः-अनुवाद ने आवश्यकता से ~8-11× अधिक आउटपुट खर्च किया।

*विधि: v1.4.0 फ़ाइलें कमिट `40dcf1f` पर रिपो से प्राप्त की गईं; शिप की गई v1.5.0 फ़ाइलों के विरुद्ध प्रति-भाषा पंक्ति-स्तरीय diff (जोड़ी गई/संशोधित पंक्तियाँ); मिश्रित-भाषा README के लिए टोकन ~3 वर्ण/टोकन पर अनुमानित। इनपुट-पक्ष लागत भी अलग होती है (incremental-edit पुराना अनुवाद पढ़ता है), लेकिन आउटपुट LLM अनुवाद का प्रमुख, सबसे महँगा हिस्सा है।*

## मशीन-स्थानीय प्रोफ़ाइल (local-profile)

गैर-मानक नेटवर्किंग वाली मशीनों पर (जैसे hosts फ़ाइल GitHub डोमेन को 127.0.0.1 पर हाइजैक करती है, साथ ही एक पोर्टेबल `gh` जिसे स्थानीय प्रॉक्सी शिम के माध्यम से चलना पड़ता है), `E:\ds harness\gh\local-profile.json` मालिक, gh एंट्री, कॉन्फ़िग निर्देशिका और ज्ञात रिपो मैपिंग को समेकित करता है। यह फ़ाइल `"never_publish": true` के साथ चिह्नित है — यह केवल मशीन पर रहती है और कभी पुश नहीं होती। इसे पढ़ने/संशोधित करने वाली कोई भी क्रिया पहले स्पष्ट रूप से ज़ोर देकर पुष्टि प्राप्त करती है।

## पर्यावरण स्व-जाँच (पहली बार पुश करने से पहले एक बार)

- `Get-Command gh` (या स्क्रिप्ट को इंस्टॉल पथों का स्वतः पता लगाने दें); अनुपलब्ध होने पर: `winget install GitHub.cli`।
- `gh auth status` एक लॉग-इन किया हुआ खाता दिखाता है (टोकन `github_pat_***…` के रूप में मास्क होता है)।
- `gh api repos/{owner}/{repo}` या `gh repo list` डेटा लौटाता है।
